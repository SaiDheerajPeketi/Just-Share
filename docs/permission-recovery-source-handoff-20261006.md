## Confirmed source defects and repair

The old page offered only Grant/Continue, cached permission status indefinitely, and had no permanent-denial settings recovery. The graph also redirected every foreground non-onboarding page to Permissions using `popUpTo(0)` whenever neither nearby method satisfied its generic checker (or legacy file access was denied), discarding the local return route and blocking unrelated pages. A Wi-Fi grant could satisfy that generic check while Bluetooth discovery still constructed its ViewModels/effects with Bluetooth denied.

The page now offers **Not now** and **Open app settings**, explicit Allowed/Not allowed/Optional states, an understandable failure/retry message when settings cannot open, and permission refresh on resume. Notifications remain optional and have their own action. The first-use overview can be skipped; returning launches go to Home. Permissions are requested for the selected method at its local discovery destination. Older discovery uses precise location, with coarse and fine requested together for Android's system choice; legacy received-file storage access is retained on Android 9 and earlier. Modern Bluetooth and Wi-Fi grants cannot unlock the other method.

Both real discovery routes call the shared `LocalDiscoveryDestination` before their discovery composables/default ViewModels are constructed. The recovery UI stays in that destination, leaving the shared transfer state and back stack intact. Not now returns to the preceding picker/home page, or Home for a direct share-sheet entry. The universal foreground redirect is removed, so ordinary pages do not depend on local discovery grants. MainActivity share ingestion, Remote Transfer authorization/provider/billing and transfer protocols are unchanged.

The gate rechecks actual grants before protected content composition as well as after permission results/resume. Discovery/progress observe local permission loss; revoke-only cleanup preserves selected URIs and stops local connections, pending bonding, discovery/hosting/retry jobs and retained Wi-Fi receivers. Wi-Fi service entry and late connection/peer callbacks check actual grants; denied cleanup stops an existing service directly instead of creating a service to send STOP. Per-action Wi-Fi retries handle a permission revocation race. Bluetooth uses legacy normal grants before Android 12 and runtime nearby grants afterward; scan cleanup checks its actual platform permission independently of another revoked sharing grant.
